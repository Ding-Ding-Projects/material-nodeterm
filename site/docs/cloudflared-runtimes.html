cloudflared connector runtimes

Choose one guided runtime for a Cloudflare Tunnel connector: a process owned by the current user, an owned Windows service, or a pinned Docker connector.

Runtime choices

  • Per-user process runs a discovered cloudflared executable without administrator rights.
  • Windows service is available only on Windows and may require administrator approval. It creates only a generated service owned by nodeterm.
  • Docker connector uses the pinned cloudflare/cloudflared image, a discovered context, and a discovered network. The default network is none.

Executable, context, network, service, and runtime lists are guided pickers. Each list has local plain-text search and an adjacent full regular-expression builder. Arbitrary shell, image, entrypoint, environment, and argument input are not accepted.

Lifecycle

Each owned connector reports unconfigured, disabled, starting, running, stopping, stopped, or failed. Start, stop, and restart show queued, starting, health-check, running, completed, failed, and cancelled progress. Health is read from the real process, service, or owned container, with a bounded timeout. A disappeared executable, context, network, service, or token produces a specific recovery action.

Security and credentials

Tunnel tokens are stored locally through the operating-system credential store when available. A restricted owner-only file is used only when that store is unavailable. The token value never enters command arguments, environment variables, project files, logs, exports, or the browser renderer.

The running connector reads a short-lived owner-only token file. Docker mounts only that file read-only, with a read-only root, dropped capabilities, no-new-privileges, bounded CPU, memory and process limits, no Docker socket, and no host network. Stopping the owned connector removes the materialized token file.

Portable intent

Project files carry only the selected runtime kind, tunnel reference, auto-start preference, network choice intent, node identity, node layout, and relationships. Credentials, executable and token paths, service names, Docker context and network identifiers, container names, process state, caches, and health results remain local. Import does not discover, launch, download, deploy, or contact a provider. The destination user explicitly configures or rebinds the runtime.

Disabled choices

Unavailable choices remain visible with the exact reason, such as missing executable, unavailable Docker, missing context or network, unavailable credential storage, unsupported platform, or required service permission. The next in-app action is shown beside the disabled choice.

Verification status

This source-only ultra-speed implementation lane did not run tests, type checks, lint, review, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or UI captures. Those checks remain unverified until the integration lane runs them against the merged commit.
