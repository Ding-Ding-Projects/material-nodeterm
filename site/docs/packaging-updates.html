Releases

Packaging & auto-update

Desktop builds are packaged per-platform and check their own update feed on launch, downloading updates in the background and surfacing a non-blocking "restart to update" card rather than interrupting active work.

Behaviour

Update checks and downloads happen silently in the background; the only visible sign is a dismissible card that appears once a download is ready, naming the new version and offering a restart. Nothing forces a restart on its own.

Configuration

Update checks and a separate opt-out telemetry ping are both gated on standard "do not track" signals and a build being an actual packaged release, not a development build.

Failure modes

If the update feed can't be reached, the app simply keeps running the current version — there is no blocking error state for a failed update check.

Security considerations

Under the project's current release policy, builds are not code-signed; this is disclosed plainly in release notes and on the update card itself rather than presented as a signed, verified update.

Verification

Exercised via the project's own local build/installer scripts, which verify the artifact they produce (path, size, checksum) rather than only trusting that packaging exited without an error.
