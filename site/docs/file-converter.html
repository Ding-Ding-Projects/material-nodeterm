Files

File converter

The installed app provides a local conversion queue under Tools. Pick files with the guided browser, choose a categorized adapter, review any lossy change, choose a destination, and start the queue. This documentation site remains a landing and documentation surface; its Turn-it-into room demonstrates structured text conversion in visitor-local browser state and is not the installed converter runtime.

Catalog and detection

Documents/PDF, images, audio, video, archives, structured data/spreadsheets, code/text, and binary encodings each have their own search with an adjacent anchored regex builder. Bundled offline adapters are enabled. Known formats that need an unbundled dependency remain visible and disabled with the exact reason.

Detection reads a bounded prefix of the selected file and inspects its bytes rather than trusting the extension alone. Adapter input limits and output validation fail closed before publication.

Queue and destinations

The queue supports bounded parallelism, progress, pause, resume, cancellation, retry, folder discovery in pages, persistent crash recovery, storage preflight, and distinct converted, failed, skipped, and cancelled outcomes.

Each item reserves the first free destination using name.ext, name (2).ext, and later suffixes. The queue tells you when it adjusted a name. Publication still uses a same-directory temporary file and an atomic no-clobber boundary, so a late race never silently replaces an output.

Completed outputs

A completed row can reveal the result in the desktop file manager or open the exact output in Visual Studio Code. The action follows the active project API, and an unavailable editor produces an honest non-blocking error.

Privacy and portability

Conversion is local to the machine that owns the active session. Source paths, destinations, queue state, progress, and editor-launch state remain in private app data and do not enter a portable project file. Importing a project starts no conversion and launches no process.

Verification boundary

The ultra-speed implementation lane intentionally did not run tests, lint, type checks, builds, packaging, installer execution, runtime interaction, reviews, security or accessibility audits, or UI captures.
