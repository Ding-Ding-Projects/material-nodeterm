Agents

Linked-agent inbox notifications

One verified agent node can ask another linked agent to reread shared coordination context. The notification is a fixed application message, not a free-form terminal write.

Behaviour

notify --node <id> names the target and carries no message text. nodeterm supplies the complete prompt, then sends it through the same authenticated, receipt-aware path used by ordinary agent messaging. The target must be an agent node that supports context links, share a persisted link with the source, and belong to the same project.

A permitted notification aimed at a busy agent is queued for delivery when the target becomes verified idle. The queue is FIFO, bounded to 16 entries per target, and expires entries after five minutes. Expiry, queue-full, delivery, and refusal outcomes are reported instead of disappearing.

Configuration

Open Settings → Agents and enable Let agents message other agents in this project for the active project. The shared agentMessaging switch is off by default. The local consent answer is kept in the project index, so a cloned project file cannot silently grant this capability on a different machine.

Turning the switch off is read live. It refuses new attempts and also prevents a queued notification from being delivered if consent or the capability changes while it waits.

Failure modes

  • A missing capability, missing local consent, or a different project returns a named refusal before any pane write.
  • An unlinked node, a plain terminal, an unsupported agent, or a target whose runtime owner cannot be proven is refused.
  • A busy or between-turn target returns queued only after the safety checks pass. The later flush rechecks the complete route.
  • A full queue returns queueFull without dropping an earlier item. A timed-out item returns expired.
  • The Server Edition reports that this desktop-only control is unsupported rather than claiming a notification was sent.

Security and portability

The fixed prompt is substituted in the main process, so even a hostile renderer request cannot change it. Verified node identity, same-project scope, runtime pane ownership, flow budgets, framed transport, and delivery traces protect the route. Trace metadata omits message bodies and credentials, and the body never travels in a shell argument.

Portable project files retain safe nodes and relationships only. Credentials, hook secrets, machine paths, process state, pane ownership records, caches, and queued runtime messages stay local. A project reopened on another computer must create fresh sessions and establish local consent before notifications can work.

Upstream provenance

The initial prototype was superseded by the authenticated main-process delivery and deliver-on-idle implementation documented here. The current flow no longer writes directly from the renderer.

Verification status

This Program 57 source lane is intentionally ultra-speed. It did not run tests, type checks, lint, reviews, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or UI captures. The source and provenance links are the implementation record; packaged behavior remains unverified until the integration lane runs its own checks.
