Agents

Agent status recovery and sidebar grouping

The application remembers a display-only last-known workflow state across restarts. The sessions sidebar can regroup sessions by workflow state without changing project order or canvas groups.

Behaviour

Live hook events remain authoritative for operation. On startup, supported local evidence is read from Claude and Gemini transcript tails or the Codex app-server status. Newer evidence can refresh the displayed state, but restored state never sends notifications, delivers messages, hibernates a process, or changes a session.

Choose Project or Status in the sidebar. Status view uses Waiting for your response, Done, Unknown, and Running sections. Unread remains a row-level notification marker, so it does not move a session into a separate workflow section.

Persistence

The choice is saved as sidebarGrouping. Project and canvas-group disclosure choices remain in sidebarCollapsedItems. The core stores the display ledger as lastKnown in the local agent-status.json file and removes it when the node is removed.

Failure modes

An unavailable transcript, malformed record, unsupported agent, unavailable Codex socket, or remote node produces no recovery evidence. The row stays Unknown or keeps its previous display-only value. A failed read is never interpreted as proof that a session finished.

Security considerations

The snapshot carries status, node and session identity, name, and a transition timestamp. It does not carry credentials, approval tickets, transcript contents, or verification proof. Recovery only reads local evidence and never launches or mutates a process.

Verification

The implementation is in the core recovery and mirror modules, the shared snapshot type, and the renderer status and sidebar modules. This lane intentionally did not run tests, type checks, builds, packaging, runtime interaction, accessibility checks, or captures. Release verification remains pending.
