AWS CDK manager

The desktop manager selects a local folder through the native picker, reviews its CDK app command, synthesizes templates, shows a diff, and deploys only after the exact diff is acknowledged.

Review-first flow

  1. Choose the folder containing cdk.json, then inspect it.
  2. Read the app command, context keys, known manifests, and warnings before approving trust.
  3. Run cdk synth and select the synthesized stacks with the local search field.
  4. Open cdk diff, read the complete output, and acknowledge it.
  5. Deploy the reviewed stack set. Removal and replacement changes open the two-key confirmation surface first.

Portability and privacy

Portable project data contains safe intent only, such as an app label and stack names. The selected folder, context values, credentials, profiles, generated templates, process state, and command output remain local. Importing a project does not run CDK or contact AWS.

Accessibility and failure states

The manager uses labelled controls, visible focus, keyboard-operable checkboxes, bounded scrolling output, responsive layout, and a local plain-text stack search with an adjacent anchored full regex builder. Missing CDK, an invalid folder, expired review, oversized output, cancellation, and a stale diff all report an actionable message.

Verification

This lane intentionally did not run tests, type checks, lint, security checks, accessibility checks, builds, packaging, installer execution, runtime interaction, or captures. The implementation is present, while release-grade evidence remains unrun.
