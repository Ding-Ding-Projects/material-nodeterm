AWS CDK manager

The AWS CDK manager guides a local project from folder selection through trust review, dependency bootstrap, synth, diff, reviewed deploy, and reviewed destroy. It is a local management surface, not a hosted AWS console or a replacement for the installed CDK app.

Workflow

  1. Choose the project root with the folder picker.
  2. Inspect the detected application, language, runtime, entrypoint, and manifests.
  3. Review the entrypoint and manifest fingerprints, then acknowledge the intended change.
  4. Bootstrap the pinned local toolkit or run a fixed synth, diff, deploy, or destroy action.
  5. Read bounded output and generated asset hashes in the Output tab.

Safety and portability

The manager never exposes an arbitrary shell field. It executes only the project-local CDK launcher with fixed arguments and shell execution disabled. Credentials, provider sessions, caches, generated output, process state, and machine paths stay local and are omitted from portable project data. A different computer must explicitly Configure or Rebind its local folder before an operation can run.

Current verification boundary

This feature lane intentionally skips tests, type checks, lint, security and accessibility checks, installer execution, runtime interaction checks, and UI captures. Build and packaging evidence proves artifact production only.
