Remote

Server Edition

The same canvas, self-hosted on a plain HTTP/WebSocket server and served to any browser — reach your terminals and agents from anywhere without installing the desktop app on the client.

Behaviour

The Server Edition boots the identical core services the desktop app uses, behind a browser-side bridge that speaks the same protocol a real remote transport would. Editor, diff, and source-control nodes work in the browser exactly as they do on desktop; a folder/file picker replaces the native OS dialog, since a browser can't open one.

Configuration

Single-user authentication (a password plus an httpOnly session cookie, with an Origin check) protects the server; there's no multi-user account system.

Docker quickstart

docker build -t nodeterm-server .
docker run -d -p 8443:8443 \
  -e NODETERM_SERVER_PASSWORD='choose-a-strong-one' \
  -v nodeterm-data:/data \
  nodeterm-server

Open the host's own URL after it starts; the static project tour is not a proxy or pairing client. Keep /data on a volume so authentication, the workspace, and scrollback snapshots survive a container replacement.

Terminate TLS in a reverse proxy and do not expose the image's plain HTTP port directly to the public internet. A container restart also ends processes and the in-container tmux server; persisted scrollback and resumable-agent metadata support cold restore, but they cannot keep a running process alive through the restart.

Failure modes

A feature added to the desktop shell must be added to the server shell too, or it silently doesn't exist there — the project's own boundary tests enforce that core logic never imports Electron directly, but they can't detect a feature that was simply never wired into the server's side of the bridge.

Security considerations

The server listens on plain HTTP by default for local/trusted-network use; putting it on the open internet is the operator's responsibility to secure (a reverse proxy with TLS, for instance) the same way it would be for any self-hosted service.

Verification

Covered by its own smoke tests plus the shared no-Electron-import boundary test that fails the build if server code ever reaches for something Electron-only.
