Canvas

Canvas & node lifecycle

The canvas is a pan/zoom React Flow surface. Nodes are the single live source of truth for what exists — there is no separate store to fall out of sync with it.

Behaviour

Unmounting a terminal node (a project switch, most commonly) doesn't tear it down immediately — it's parked: the xterm instance and its PTY client stay alive, just detached from the DOM, so remounting shortly afterward is instant and exact. Only after a park window elapses does the real teardown happen, detaching the PTY client while the underlying tmux session keeps running. A node that stays fully offscreen for long enough (configurable, default on) is released in place: its renderer is torn down but the node stays on the canvas as a plate, reviving the moment it's approached again.

When Scroll wheel zooms is enabled, a plain wheel zooms toward the pointer. High-resolution ratchet wheels can deliver one physical detent as several packets, so packets inside a 40 ms burst share one ±50 delta budget. A later click gets a fresh budget. Wheel zoom speed persists from 0.2× through 2.0×, with 1.0× preserving the historical feel. It changes only plain-wheel zoom; modifier wheel zoom and trackpad pinch retain their fixed behavior. Missing, invalid, or out-of-range hand-edited values are clamped at the point of use.

Configuration

The offscreen-release timer, terminal GPU rendering mode, default node size, plain-wheel zoom toggle, and wheel zoom speed are all in Settings → Behavior. Desktop and Server Edition share the same renderer and settings record. The mobile companion has no wheel input.

Failure modes

A memory-reclaiming action that kills a PTY client is only free when tmux is genuinely underneath it — on the plain-shell fallback, that PTY is the shell, so the same call would kill whatever process is running inside it. Every lever that reclaims terminal memory checks whether the session actually has live work in progress before it acts.

A malformed wheel speed never becomes an unbounded exponent: the renderer uses 1.0× for a missing or non-finite value and clamps finite values to 0.2×–2.0× without rewriting the settings file while reading it.

Security considerations

Not applicable beyond what's already covered under terminal sessions and node kinds — the canvas itself holds no secrets of its own.

Verification

Park/release/revive timing is covered by dedicated tests asserting the two invariants that matter most: the visibility observer must survive the exact re-render that would otherwise kill it, and the "protect live work" gate must never guess a session is safe to kill when it doesn't actually know.

The wheel-speed implementation lane intentionally did not run tests, lint, type checks, builds, packaging, runtime interaction, reviews, audits, or captures. The integration lane must exercise multi-packet bursts, budget refill, point-of-use clamping, persistence, and unchanged modifier/pinch behavior in the built surfaces.
