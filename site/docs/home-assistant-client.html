Integrations

Home Assistant multi-instance client

The Home Assistant service node manages several local machine connections. It is an installed-app integration, not a browser imitation or a hosted proxy.

Configure an instance

Enter a label, an HTTPS base URL, and a long-lived access token in the guided panel. Real installations require HTTPS. Plain HTTP is accepted only for localhost, 127.0.0.1, or ::1 during local development. URLs with credentials, unsupported schemes, fragments, or control characters are rejected.

The instance list, endpoint, enabled state, and node bindings stay in the application's local data directory. The token is stored separately through the host credential store and is never returned to the renderer or written to a project file.

Discovery

After connecting, the client reads state and entity registries, services, devices, and areas through Home Assistant's documented REST API. It then authenticates to /api/websocket and subscribes to state_changed. Entity rows update live and can be selected to bind an entity to the current canvas node.

Availability and recovery

The panel distinguishes disabled, unconfigured, connecting, connected, reconnecting, offline, authentication failure, invalid endpoint, timeout, and other request errors. Registry responses are bounded and malformed or oversized data is rejected rather than partially applied. Reconnect retries use bounded exponential backoff.

Each connection has a generation. Editing the endpoint, changing its token, disabling it, disconnecting, or removing it closes the prior WebSocket and invalidates its pending work. A late response from the old generation cannot overwrite the current snapshot.

Search and accessibility

Entities are shown in a keyboard-operable, screen-reader-named list with visible focus and bounded scrolling. Plain-text search is the default. The adjacent regex control opens the full anchored builder for this list, including syntax feedback and flags.

Portable projects

Schema 3 project files carry the service node's safe label, kind, layout, and relationships. They omit Home Assistant URLs, tokens, bindings, registry caches, connection state, and host identity. Reopening the project on another computer presents a local Configure or Rebind route and never performs a network call during import.

Verification status

The current implementation lane was delivered without tests, builds, runtime interaction, or screen captures. Release verification still needs an isolated Home Assistant fixture covering REST discovery, WebSocket reconnect, stale-generation cancellation, token rejection, both shell boundaries, and the packaged runtime.
