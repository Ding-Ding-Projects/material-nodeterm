Canvas

Node kinds

Every object on the canvas is a React Flow custom node. Alongside terminals, sticky notes, groups, editors, diffs, and service nodes, each Multiverse or AWS Universe child canvas owns one fixed Shop node; the root canvas has none.

Behaviour

  • terminal — a real shell (xterm + tmux). Agent nodes are a preset of this kind that launch an agent CLI as their first command.
  • sticky — a colored, collapsible text note that can be linked to a terminal node to attach the note as live context.
  • group — a real parent/child frame; frames can nest to any depth and can be bound to a git worktree, so every node created inside one inherits that worktree's path as its working directory.
  • editor — a Monaco code editor bound to a file path, with an image-preview mode for common image formats.
  • diff — a read-only Monaco diff view comparing a file's staged or unstaged changes.
  • shop — the one deterministic, scope-bound catalog entry point owned by a Multiverse or AWS Universe child canvas. It cannot be moved, grouped, duplicated, or deleted.

Configuration

Default node size for new terminal and agent nodes is set once in Settings and applies to every subsequently created node; existing nodes keep whatever size they were last resized to.

Failure modes

A node's id must never change once created — it is also the tmux session name for terminal nodes, so changing it would orphan the running session from the node that used to own it. A Shop id is derived from its universe canvas id and is repaired on import when missing or duplicated.

Security considerations

Editor and diff nodes read and write real files on disk (or on a remote host for SSH projects) — the same access any local editor would have, no more and no less.

Verification

Each node kind has its own focused test coverage for creation, persistence, and its kind-specific behaviour (e.g. the diff node's staged/unstaged toggle, the group node's re-fit-to-children logic). The Shop lane's implementation is present, but tests, builds, runtime interaction, and captures were intentionally not run for issue #17.
