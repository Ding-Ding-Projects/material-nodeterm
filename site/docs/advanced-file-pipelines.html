File conversion

Advanced media, archive, PDF, OCR, and structured-data pipelines

The installed desktop app is the primary runtime. This documentation page explains the feature and does not convert files itself.

Bundled operations

The File converter runs PDF text extraction, inspection, split-to-ZIP, merge-from-ZIP, first-page extraction, reverse ordering, clockwise page rotation, metadata removal, supported image conversion, local English OCR, bounded ZIP inventory, deterministic JSON key ordering, and the structured-data conversion mesh. Audio, video, TAR, 7-Zip, DOCX, HEIC, and ICO rows remain visible with an exact unavailable reason when no packaged adapter exists.

Guided queue

File and folder pickers, byte-based detection, categorized searches with adjacent regex builders, lossy-operation acknowledgement, destination capacity preflight, pause, cancellation, retry, partial results, and restart recovery are part of one persistent queue. Output is validated and published atomically.

Resource limits

  • Images: 40 million pixels, one frame, and the adapter byte ceiling.
  • PDF: 500 pages and the adapter byte ceiling.
  • ZIP inventory: 2,048 entries and 512 MiB declared expanded data, with unsafe paths refused.
  • OCR: packaged English data only, with no network fallback.

Portable intent

A transferred project keeps only the operation identity and resource profile. It omits paths, credentials, provider sessions, processes, host and machine identifiers, caches, and generated output. Import performs no conversion or external action. On another computer, use Configure, Rebind, Adopt, Deploy, Locate Asset, or Leave Unbound.

Verification boundary

This ultra-speed implementation lane did not run tests, type checks, lint, builds, packaging, installer execution, runtime interaction, reviews, audits, or UI captures.
