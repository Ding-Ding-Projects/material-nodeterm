Platforms

Windows support

nodeterm ships as a native Windows desktop app alongside macOS and Linux, using the same Electron shell and the same tmux-backed terminal model.

Behaviour

The Windows build uses a frameless window with its own Material-Design title bar rather than the OS default chrome, matching the macOS and Linux builds. Terminal sessions on Windows still go through tmux where a compatible tmux binary is available (via WSL or a bundled build); where it isn't, sessions fall back to a plain shell with no cross-restart continuity, exactly as on any other platform without tmux.

Configuration

Default shell selection (PowerShell, cmd, WSL) lives in Settings, alongside the same tmux/scrollback options every platform shares.

Failure modes

Windows path handling — drive letters, backslashes, reparse points — is the most common source of platform-specific bugs in file and git operations; every path-handling code path is expected to be exercised on Windows specifically rather than assumed to work by analogy with POSIX behaviour.

Security considerations

No code-signing is applied to Windows builds under the project's current release policy; installers are unsigned and may trigger the OS's unknown-publisher warning. This is disclosed, not hidden, in the release notes for each build.

Verification

Exercised through the project's own build scripts (build.bat, build-installer.bat) which install every toolchain dependency themselves and produce a real, installable artifact rather than a developer-only dev-mode build.
