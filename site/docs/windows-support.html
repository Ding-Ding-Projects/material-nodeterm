Platforms

Windows support

nodeterm ships as a native Windows desktop app with detected native and WSL shell profiles, real ConPTY terminals, and a standalone session host that keeps them alive across app restarts.

Behaviour

The Windows build uses a frameless window with its own Material-Design title bar rather than the OS default chrome, matching the macOS and Linux builds. Local shells are hosted directly through ConPTY; nodeterm does not embed Microsoft Windows Terminal.

On stock Windows, where there is no native tmux, nodeterm's standalone session host owns each live PTY and a headless terminal buffer. Closing or crashing the desktop app detaches its clients while the host and shell keep running. Relaunching the app reattaches to the same named session and reconstructs its screen. A tmux installed only inside WSL is not treated as a native Windows tmux.

Configuration

Settings → Shell lists stable profiles for Automatic, PowerShell 7, Windows PowerShell, Command Prompt, Git Bash, each installed WSL distribution, and an advanced custom executable. Automatic tries PowerShell 7, then Windows PowerShell, then %COMSPEC%/cmd.exe. Detection can be refreshed after installing or removing a shell or WSL distribution.

One-click creation uses the saved default. Profile-aware menus can snapshot a different profile on a new node, so later default changes affect only newly created nodes. If an explicit profile disappears, it is shown as unavailable with its reason; it never silently opens another shell or WSL distribution.

For WSL profiles, the selected distribution translates the Windows project directory with its own wslpath. A trusted distro-side guard independently enters that translated directory before starting the configured default shell, so a directory removed during launch fails closed instead of silently opening in /.

Switching and trust boundary

Restart with profile… is available for local terminal and agent nodes. Its destructive confirmation states that the live process and persistent session will end; cancellation changes nothing.

The renderer and canvas carry only a stable profile id. Executable paths and arguments remain private to the trusted core and are resolved again immediately before spawn. Profile choices, custom shell values, and advanced SSH execution fields stay machine-local and are stripped from shared project files and peer mutations.

Failure modes

A machine reboot ends the session-host process and every live shell it owned. On the next launch, nodeterm can replay its capped scrollback snapshot and resume a supported agent conversation, but it does not claim the original OS process survived. A provisional or rejected session-host attach fails closed instead of being indexed as persistent or replaced by a different shell.

Windows path handling — drive letters, backslashes, reparse points — remains a common source of platform-specific bugs in file and git operations; path-sensitive code must be exercised on Windows rather than assumed to work by analogy with POSIX behaviour.

Security considerations

No code-signing is applied to Windows builds under the project's current release policy; installers are unsigned and may trigger the OS's unknown-publisher warning. This is disclosed, not hidden, in the release notes for each build.

Verification

Resolver, spawn-boundary, settings, persistence, fail-closed attach behaviour, and profile-specific app localization have focused automated coverage. Packaged Windows interaction and capture evidence for the profile picker, each available profile, destructive switching, and post-relaunch reattachment is still pending; this page does not claim those gates have completed.
