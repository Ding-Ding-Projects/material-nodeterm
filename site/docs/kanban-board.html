Canvas

Kanban board

Every project doubles as a Trello-style board. Cards aren't a separate data model — they're the same live session nodes on the canvas, just viewed as a board instead of a spatial map.

Behaviour

Dragging a card between columns changes only board metadata (which column it's assigned to) — it never moves the underlying canvas node or changes its group. A terminal card opens into a live second view of the same tmux session, so typing in the board's card modal and typing on the canvas both reach the exact same running process.

Cards support assignees, a due date, priority, and a per-card comment/activity feed backed by an append-only local log file, so the history of who did what to a card survives independently of the canvas state itself.

Configuration

Column names, order, and the assignment of sessions to columns are all part of the project's own file, so they travel with the project the same way node positions do.

Failure modes

A board referencing a node that no longer exists prunes that stale assignment automatically rather than showing a dead card; deleting the last column doesn't break anything because an "Ungrouped" column always exists as the catch-all destination.

Security considerations

Not applicable beyond what's already covered under source control and terminal sessions — the board is a view, not a new access boundary.

Verification

Board shape validation runs on every load path so a hand-edited or older-format board file degrades to a fresh default rather than crashing the render.
