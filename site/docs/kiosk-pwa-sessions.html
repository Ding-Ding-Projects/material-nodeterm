Remote and services

Kiosk and PWA sessions

Choose a secure URL for a popup-free kiosk surface, or choose an installed web app for a PWA session. Both are real canvas sessions with explicit lifecycle and recovery states.

Guided selection

The setup surface requires a display name and a reviewed target. HTTPS is required, while HTTP is accepted only for localhost development. PWA mode requires a host-detected installed app. The installed-app list has plain-text search and an adjacent anchored full regex builder. If discovery is unavailable, the list says so and does not invent choices.

Portable intent and local profile

Schema 3 carries only the mode, target, display name, and requested permission names. Cookies, local storage, credentials, profile state, permission grants, process state, window handles, and host identifiers remain local. Import reconstructs intent only and performs no navigation, launch, download, deployment, or provider change.

Lifecycle and permissions

Sessions move through idle, starting, running, stopping, stopped, unavailable, and error. Exit and Retry are explicit controls. Popups are disabled. Notifications, camera, microphone, location, and clipboard access are denied unless requested in the intent, and the current surface still denies browser permission events until a host confirmation route exists.

Verification

This ultra-speed implementation lane did not run tests, type checking, lint, review, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or captures.
