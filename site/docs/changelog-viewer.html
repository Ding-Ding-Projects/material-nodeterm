Changelog viewer

Every recorded release, generated from the repository's real CHANGELOG.md — never invented — with a date-range filter, a full-text search wired to an anchored regex builder, and a commit link on every entry.

Behaviour

The date range and the text search compose rather than override each other — narrowing one never silently resets the other. Every entry links its exact commit SHA back to the repository, so a claim in the changelog is always one click from the code that made it.

Configuration

Range presets (last 30 days, last 90 days, all time) sit beside a native date-range picker, which already accepts both a locale-formatted date and a typed ISO date without any extra parsing on this site's part.

Failure modes

A start date after the end date shows an inline note and zero results rather than silently swapping the two values or throwing.

Security considerations

Regex evaluation in the search field is local only — nothing is sent anywhere — and every pattern and sample is length-capped before it's ever compiled.

Verification

The underlying data file, site/content/changelog.json, is generated directly from CHANGELOG.md's real entries; a parse that can't confirm a version, date, and commit for an entry drops it rather than emitting a partial or fabricated record.
