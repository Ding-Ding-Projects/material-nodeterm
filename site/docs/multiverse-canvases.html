Canvas

Multiverse child canvases

One project can contain a rooted hierarchy of scoped child canvases. The project canvas is depth 0, and children may nest through depth 8.

Create and navigate

The canvas app bar shows the active hierarchy path and depth. Its navigator searches every canvas locally with plain text by default and an adjacent full regex builder. The guided creator uses a separate searchable parent picker, states the resulting parent and depth, requires a name, and explains exactly why a depth-8 parent cannot accept another child.

Scoped state

Each child owns its viewport, nodes, bridges, ropes, title, parent, order, and depth. New children start with one deterministic scoped Shop. The root has no Shop. Switching commits the outgoing scope before loading the selected canvas.

Persistence and portability

Ordinary project files preserve the hierarchy. Portable schema 3 carries every child, its scoped nodes, and relationships tagged with the owning canvas identifier. Import validates identifiers, titles, parent ordering, depth, count, node lists, and viewports before rebuilding the hierarchy.

Privacy and side effects

The hierarchy contains no credentials, provider sessions, process state, runtime handles, or local terminal executable settings. Import reconstructs data only. It does not launch a process, download anything, contact a provider, or make a network request.

Verification boundary

The issue #33 ultra-speed lane did not run tests, type checks, lint, builds, packaging, reviews, audits, runtime interaction, accessibility checks, security checks, installer execution, or captures.
