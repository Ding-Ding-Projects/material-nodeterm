This site

Personal vocabulary

Choose your own local versioned JSON file, and this site's prose is rewritten with it — until then, every surface shows its original wording, because this site ships no built-in mappings of its own.

Behaviour

The upload control is visible even before a file exists, with distinct no-file, loaded, invalid, and cleared states. A file is validated completely before anything is applied — an invalid file never applies partially, and the previous valid file stays active. Replacements are applied only at the user-facing prose text boundary (this site's central copy-rendering function), never to code, URLs, identifiers, or paths.

Configuration

The schema is identical to the desktop renderer: version 1, a 256 KB UTF-8 byte cap, maximum depth and node budgets, a maximum of 2,000 entries, bounded key and value lengths, string-only values, duplicate-key rejection, and rejection of unsafe keys like __proto__. The persisted browser cache adds only entryCount and savedAt, validates their consistency, and expires after 30 days. See the exact contract in site/app/shared/vocabulary-state.js.

Failure modes

A rejected file leaves the previous, still-valid vocabulary (if any) untouched and active — a bad upload never silently wipes out a working one.

Security considerations

Nothing is ever uploaded anywhere — parsing, validation, caching, and replacement all happen locally, in this browser only, with no network request of any kind. The upload is a semantic JSON file picker, not a free-text substitute for the contract.

Verification

Bounds and rejection rules are all in validateVocabularyJson(), with the persisted envelope checked by validateVocabularyCacheJson(). Both return either a fully validated result or a specific rejection reason — never a partial success.
