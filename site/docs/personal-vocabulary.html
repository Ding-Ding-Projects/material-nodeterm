This site

Personal vocabulary

Upload your own local word → replacement JSON file, and this site's prose is rewritten with it — until then, every surface shows its original wording, because this site ships no built-in mappings of its own.

Behaviour

The upload control is visible even before a file exists, with distinct no-file, loaded, invalid, and cleared states. A file is validated completely before anything is applied — an invalid file never applies partially. Replacements are applied only at the user-facing prose text boundary (this site's central copy-rendering function), never to code, URLs, identifiers, or paths.

Configuration

The schema is one version, bounded on every axis: a file-size cap, a maximum entry count, bounded key and value lengths, string-only values, and rejection of unsafe keys like __proto__. See the exact numbers in site/app/shared/vocabulary-state.js.

Failure modes

A rejected file leaves the previous, still-valid vocabulary (if any) untouched and active — a bad upload never silently wipes out a working one.

Security considerations

Nothing is ever uploaded anywhere — parsing, validation, and replacement all happen locally, in this browser only, with no network request of any kind.

Verification

Bounds and rejection rules are all in one function, validateVocabularyText(), which returns either a fully validated result or a specific rejection reason — never a partial success.
