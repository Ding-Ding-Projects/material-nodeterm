Remote and services

Docker host manager

The Docker host canvas node discovers Docker CLI contexts on the current computer and offers separate guided surfaces for containers, images, volumes, networks, Compose projects, statistics, logs, and fixed typed container tasks.

Guided controls

Every resource area has local plain-text search and an adjacent anchored regex builder. Container creation uses an allowlisted image catalog, generated ownership label, bounded CPU, memory and PID settings, dropped capabilities, no-new-privileges, a read-only root by default, and no network by default. Lifecycle jobs report real progress and cancellation.

Safety and portability

The renderer submits a closed action and discovered resource id. The desktop main process validates it and invokes Docker with an argument array, never a shell string. Context endpoints, SSH identities, credentials, Compose paths, live ids, statistics, logs and process state remain local. Portable schema 3 data contains only safe neutral intent, and import never contacts or changes a host.

Failure recovery

An unavailable context or failed resource command stays distinct from an empty resource list. Repair the named Docker context and retry from the same surface. A resource that disappeared is never replaced with another id. Server Edition reports this desktop-owned capability as unsupported.

Verification

This ultra-speed implementation lane did not run tests, type checking, lint, review, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or captures.
