Canvas

Bounded wheel zoom and speed

The desktop and Server Edition canvas use one bounded wheel-zoom path, so a high-resolution ratchet wheel cannot turn one physical click into several compounded zoom steps.

Behaviour

Packets arriving within 40 ms share one ±50 deltaY budget. A packet after the burst window starts a fresh budget. Reversing direction after the budget is exhausted returns no free counter-step, because that packet is treated as device jitter.

Wheel zoom speed applies only to plain-wheel input. The persisted range is 0.2× through 2.0×, and 1.0× preserves the historical zoom exponent. Modifier wheel zoom and trackpad pinch retain the fixed multiplier.

Configuration

Open Settings → Behavior, enable Scroll wheel zooms, and adjust Wheel zoom speed. The slider uses 0.1× steps and reports its current value to assistive technology. Its explanation and provenance line follow the selected language mode and funny-level voice while the numeric multiplier stays factual.

Failure modes

Hand-edited settings are validated where they are consumed. Missing, non-numeric, and non-finite values use 1.0×. Finite values below 0.2 are clamped to 0.2, and values above 2 are clamped to 2. Reading the setting does not rewrite the file, so the original value remains inspectable.

Security considerations

The multiplier and burst state contain no credentials, paths, session data, or user content. Raw wheel packets stay local to the renderer. Server Edition receives the same bounded settings value and never receives wheel-event data.

Verification

The implementation lane intentionally did not run tests, lint, type checks, builds, packaging, runtime interaction, reviews, audits, or captures. The integration lane should exercise an oversized packet, a multi-packet detent, a split-budget burst, a post-window refill, an exhausted reversal, malformed values, persistence, and unchanged modifier/pinch behavior in the built surfaces.
