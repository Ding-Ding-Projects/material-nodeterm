Canvas

Projects & tabs

A project is one canvas — one pan/zoom page of nodes, with its own working directory. Everything you build spatially belongs to exactly one project, and every project is its own tab.

Behaviour

Switching between project tabs unmounts the previous project's terminal nodes — their tmux clients detach, but the sessions themselves keep running — and mounts the new project's nodes, reattaching any of its own terminals. Project order is a single shared order between the tab bar and the sessions sidebar; both reorder the same underlying list via drag-and-drop.

Closing a project from its tab menu is non-destructive: it hides the tab and stops attaching its terminals, but keeps every node and setting on disk, with the tmux sessions still running underneath. It reappears in a "Recently closed" list on the welcome screen. Permanent deletion — which does tear down the underlying sessions — only happens from that recently-closed list's own remove action.

Configuration

A project's working directory is set once, via a folder picker, and every terminal or agent node created afterward opens there by default. Opening the same folder twice reuses the existing project rather than creating a duplicate.

Failure modes

If a project's on-disk file becomes unreadable, its tab renders greyed-out as "unavailable" rather than silently disappearing — nothing is dropped without being shown as broken first.

Security considerations

Project files are plain, git-shareable JSON next to the project's own code; there is nothing in them that should be treated as secret, but they do record file paths and node titles, which is worth knowing before committing one to a shared repository.

Verification

Covered by the persistence layer's own test suite, exercising save/load round-trips, the "close vs delete" distinction, and reordering.
