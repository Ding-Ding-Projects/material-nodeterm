AWS identity manager

Settings → AWS identity provides a guided local surface for AWS profile metadata, SSO login, role sessions, MFA, caller identity, permissions, regions, and endpoint overrides.

What it does

  • Reads profile metadata from the local AWS configuration files without returning credentials or SSO tokens.
  • Starts AWS SSO through supported PKCE login, with device-code mode for headless environments.
  • Assumes a validated IAM role and writes one-time MFA input only through protected stdin.
  • Checks caller identity and IAM policy permissions, reporting unknown instead of guessing allowed.
  • Lists verified regions and stores HTTPS endpoint overrides in machine-local application data.

Credential boundary

Access keys, role credentials, SSO tokens, MFA values, credential-process output, private paths, and provider cache contents never enter project files, portable exports, renderer state, logs, or ordinary history. Import performs no network request, provider mutation, process launch, or download.

An imported credential_process remains untrusted until the user explicitly reviews it. The manager does not accept arbitrary shell text or execute a command supplied by project data.

Honest failure states

Missing AWS CLI, unavailable SSO, failed role trust, invalid MFA, unavailable caller identity, failed IAM simulation, and offline region discovery remain visible states with recovery guidance. An unknown permission result is not treated as permission.

Verification status

The implementation is present in the shared contract, core manager, IPC registrars, preload, browser bridge, and Settings surface. Automated checks, builds, packaging, runtime interaction, and captures remain pending for the owning integration pass.
