Integrations

Shared provider services

Desktop and Server Edition use one core service for provider catalogs, connected account metadata, sealed credentials, OAuth PKCE callbacks, resource discovery, and destination-only bindings.

Guided provider setup

The binding wizard shows connected accounts and provider-verified resources as searchable lists. Each list has its own adjacent regex builder. Missing adapters remain visible with the exact reason, and unavailable controls do not pretend to connect.

Local secrets and portable intent

Credentials, provider sessions, OAuth state, callback data, machine paths, host identity, caches, and runtime data stay in private application storage. Projects carry only safe feature intent, layout, relationships, capabilities, and settings. Import never starts sign-in, calls a provider, deploys, downloads, launches a process, or binds a resource.

Callback safety

OAuth adapters use authorization-code PKCE with a high-entropy verifier, SHA-256 challenge, single-use state, a ten-minute expiry, an exact loopback callback route, and a bounded waiting ledger. Callback state is consumed before exchange so it cannot be replayed.

Implementation status

The shared contracts and core service are in src/shared/provider-services.ts and src/core/provider-services.ts. This ultra-speed lane did not run tests, type checks, lint, reviews, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or UI captures. Provider-specific adapters remain separate delivery lanes.
