Exports, notifications & local history

Every notification and every meaningful settings change on this site is recorded locally and stays reviewable — with full bulk-select actions — and every one of those data sets can be exported in whichever format best represents it.

Behaviour

Notifications (success/info messages, and warnings/errors that persist until dismissed) stay reviewable in a Notifications panel after they disappear from the corner toast stack. A separate Local history panel records a plain, human-readable description of every meaningful settings change — a language mode switch, a vocabulary file loaded, a lock created — and keeps the prior saved values so putting a change back really restores them. Putting that restore back works too. Record-only events such as exports and conversions stay labelled as log entries and do not pretend to be reversible; deleted history rows stay deleted after a reload. Oldest entries are pruned automatically once the cap is reached.

Both lists get the full bulk-action contract: multi-select with shift-click ranges, a select-all that states what it means, inverse selection, and a reviewable count-and-preview before anything destructive runs.

Configuration

The Export panel offers your settings, notification history, and local history each in JSON, JSONL, YAML, TOML, XML, CSV, TSV, Markdown, and HTML — whichever format best fits how you want to use the data next.

Failure modes

A format that can't faithfully represent nested data (CSV, TSV, Markdown, HTML) discloses exactly what it will flatten before the download runs, never after.

Security considerations

Nothing here is uploaded — every export is generated in this browser and handed to you as a local file download.

Verification

All encoders live in one shared module, site/app/shared/exportFormats.js, so every export surface on this site uses exactly the same, single implementation of each format rather than nine slightly-different CSV writers.
