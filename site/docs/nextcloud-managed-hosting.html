Hosted services

Managed Nextcloud, no Docker socket

A fixed, guided profile for Nextcloud web, PostgreSQL, and Redis on a private network. It starts locally first and keeps tunnel exposure as an explicit later handoff.

What it manages

The desktop and Server Edition use a typed lifecycle manager. You choose only a supported release and bounded private port. The surface does not accept arbitrary images, commands, entrypoints, Compose text, or environment values.

  • PostgreSQL, Redis, and web services use fixed official image families.
  • Three named volumes hold database, data, and configuration state.
  • Secret files stay in the local application-data directory and never enter the project file.
  • Readiness waits for database, Redis, and the web health endpoint.

Recovery sequence

Updates back up first, replace the web image, and wait for readiness. Backups contain a database dump plus data and config archives. Restore stops the managed services, restores all three resources, and reruns readiness. Rollback recreates the last recorded release. Deleting volumes requires the app's two-key confirmation.

Private first

The listener binds to loopback. Handoff preparation is available only after all readiness checks are healthy, and it only marks the service eligible for the dedicated tunnel workflow. It does not create a tunnel or change DNS.

Implementation and evidence

Implementation files: src/shared/nextcloud.ts, src/core/nextcloud/manager.ts, src/core/nextcloud/register-ipc.ts, and the service-node panel. The ultra-speed implementation boundary intentionally skipped tests, type checks, lint, builds, packaging, installer execution, runtime interaction, and UI captures. The feature is therefore documented as implemented but not yet release-verified.
