Linux ISO VM node

The Linux ISO VM is a one-shot canvas node for a real Linux guest. It is separate from WSL: WSL provides a distribution-backed shell, while this node starts an isolated QEMU machine.

Guided setup

Choose Managers → New manager… → Linux ISO VM. Use the native file picker for the ISO and, for persistent install mode, a qcow2 or raw disk. The node accepts no arbitrary QEMU flags or shell commands.

  • Disposable live is the default. QEMU snapshot mode sends writes to a throwaway overlay.
  • Persistent install keeps the selected disk so an installer can create a guest that returns later.

Memory is bounded to 512–32768 MiB and CPUs to 1–16. Network is off by default and only user-mode networking can be enabled explicitly.

Persistent install mode includes a folder picker that checks free space and creates a qcow2 disk with bundled qemu-img. Existing disks are detected from their bytes as qcow2 or raw. An optional expected ISO SHA-256 is checked before startup, with expected and actual values shown in the node.

Lifecycle

The bundled QEMU process receives a fixed validated argument vector. WHPX is probed by the emulator itself, with TCG reported as the fallback. Startup waits for QMP and the loopback VNC display sockets before reporting running. Stop sends QMP quit and uses bounded escalation if needed. Desktop users can open the loopback display; Server Edition never exposes a misleading browser-localhost URL.

Portability and recovery

Mode, resource limits, network choice, and acceleration preference are portable project settings. ISO and disk paths are machine-local. A clone on another computer remains present and asks the user to locate those assets again. Import performs no process launch, download, or network call.

Missing assets and missing bundled tools remain visible as actionable errors. Runtime process state, QMP ports, overlays, and generated data never enter the project projection.

Verification boundary

The ultra-speed delivery lane intentionally did not run tests, type checks, lint, reviews, security checks, accessibility checks, installer execution, runtime interaction checks, or UI captures. Build and packaging evidence proves artifact production only.
