Hosted service node

Open WebUI hosting

Run the pinned official Open WebUI image with persistent data, reuse local Ollama, or choose an OpenAI-compatible provider. This page documents a guided desktop node, not the hosted service itself.

Guided setup

The node starts with local Ollama, model llama3.2, and port 3000. Pick a discovered local or SSH Docker context. The context and model searches use plain text by default and each has an adjacent anchored regex builder.

Deploy creates a node-owned named volume and container from ghcr.io/open-webui/open-webui:v0.6.37. Local Ollama uses http://host.docker.internal:11434. The OpenAI-compatible choice keeps only a validated base URL locally and completes API-key entry in Open WebUI's own first-user setup.

Health and first-user setup

Health states are explicit: unbound, running, first-user setup required, stopped, unreachable, or failed. The Open page action is enabled only after a verified local response. SSH deployments say when a tunnel is required rather than presenting a local URL as though it were remote.

Persistent data and recovery

Backup selects a local folder and writes a timestamped .tar.gz from the node-owned volume. Restore selects a local archive, validates its paths, and requires the existing two-key confirmation before replacing data. Update records the prior image, while rollback recreates the owned container from that recorded image. Operations report progress, cancellation, and partial failure.

Portable intent

Project files carry provider mode, model, Ollama reuse, and port only. Context names, container and volume identifiers, URLs, local paths, process state, and credential references stay in local application data. Import therefore performs no network call, deployment, pull, provider mutation, process launch, or download.

Verification boundary

The ultra-speed implementation lane intentionally did not run tests, type checks, lint, reviews, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or UI captures. Those checks remain a separate release task.
