Integrations

Open WebUI hosting node

The node runs the official pinned image ghcr.io/open-webui/open-webui:v0.8.3 on a private loopback port, with persistent data stored in a named Docker volume.

Guided setup

Choose a discovered Docker context and a bounded host port. Choose either reuse of an existing local Ollama API or an OpenAI-compatible HTTPS endpoint. The surface accepts no custom image, arbitrary command, entrypoint, Compose text, socket, or environment editor. An optional credential reference names the operating-system vault entry only; the key never enters the canvas or Docker arguments.

Bootstrap and health

Authentication stays enabled. After the local /health endpoint responds, the node reports “Ready for the first user” until somebody completes Open WebUI's own registration. nodeterm does not create an account or claim that registration happened.

Persistent recovery

Backup creates a dated, byte-sized copy of the volume. Restore, update, and rollback preserve an automatic copy before changing the container or its data. A failed action reports the concrete reason and leaves the recovery copy available.

Private-first tunnel boundary

The node never exposes a public port or creates a tunnel automatically. A separate handoff is enabled only after local health is ready, and returns the local URL to the guided tunnel flow.

Portability

Project files keep safe display intent only. Docker context, volume, container state, local URL, credentials, and runtime data remain local. Import performs no network request, image pull, process launch, deployment, or tunnel action.

Verification note

This ultra-speed lane intentionally did not run tests, type checks, lint, security or accessibility checks, builds, packaging, installer execution, runtime interaction, or captures. Artifact and release verification must record that boundary honestly.
