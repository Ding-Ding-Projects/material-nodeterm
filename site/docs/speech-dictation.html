Input

Speech / dictation

Voice-to-text input for any terminal, using on-device Whisper — nothing is sent to a server, and nothing is ever submitted automatically.

Behaviour

Hold a chord, speak, review the transcribed text, then explicitly choose to send it (with a trailing Enter) or insert it without sending. Every step up to the explicit send/insert action is reversible; the app never guesses that a transcription is finished and submits it on your behalf.

Configuration

Model size is a tradeoff between accuracy and resource use — a small free tier is always available, larger models are a premium tier. Only one model is kept loaded in memory at a time.

Failure modes

If the on-device transcription engine's native dependency isn't available on a given machine, dictation degrades to a clear "unavailable" message rather than a silent no-op button.

Security considerations

Audio capture requires the browser's or OS's own microphone permission prompt — the app never bypasses or pre-answers that prompt itself.

Verification

The audio capture path (a WebAudio worklet with a fallback) and the model download/orphan-sweep logic have their own test coverage; the native ABI rebuild step this depends on is a known gap not yet exercised in CI, and is recorded as such rather than assumed to be fine.
